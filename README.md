# 🎙 Silero TTS Studio

Профессиональная рабочая среда (GUI) для генерации аудиокниг, подкастов и озвучки текста с использованием нейросети Silero.

Программа оптимизирована для создания длинных аудиокниг с экономным использованием API-лимитов. Поддерживает быстрый RAM-индекс кэша, локальную постобработку звука (FFmpeg), работу с глоссариями, извлечение текста из электронных книг (EPUB, FB2, DOCX) и пакетную сборку с редактированием ID3-тегов.

## 🧰 Работа без API-ключа

Silero TTS Studio можно использовать и как набор локальных инструментов для подготовки книг и обработки уже существующего аудио:

* извлекать текст и главы из EPUB, FB2 и DOCX, сохранять книгу одним TXT либо нарезать TXT на главы по RegEx; шаблоны имён поддерживают, в частности, автора EPUB/FB2 через `{author}` и стартовую нумерацию `{num:N}` (например, `{num:0}` или `{num:15}`);
* проверять нормализацию, редактировать глоссарий и сохранять подготовленный TXT без синтеза и расхода API-лимитов;
* группировать и разгруппировывать готовые MP3/WAV/OGG/Opus, автоматически разбивать их на тома, склеивать или конвертировать с локальными FFmpeg-эффектами, аудиопрофилями, тегами и поддерживаемыми форматом обложками;
* просматривать, прослушивать, оптимизировать, архивировать и перекодировать уже заполненный кэш.

> **Важно:** создание новой речи остаётся API-функцией и требует API Token и доступа к настроенному endpoint. Обычная пересборка полностью совпавшего проекта берёт речевые фрагменты из кэша без повторных запросов, но запускается через режим синтеза, который всё равно проверяет наличие токена.

## 🚀 Основные возможности

* **⚡ RAM-индекс кэша:** Индекс доступных фрагментов хранится в оперативной памяти, совпавшие фразы переиспользуются без повторного API-запроса, а финальные FFmpeg-сборки могут выполняться параллельно. На полностью кэшированных проектах это обычно намного быстрее повторного синтеза; фактическое время зависит от CPU, диска и выбранного профиля вывода.
* **📖 Умный HTML-парсер книг:** Алгоритм очистки текста при импорте из EPUB и FB2 больше не разрывает абзацы из-за внутренних тегов `<br/>`, `<em>`, `<strong>` или оформления кода.
* **📍 Навигатор и авто-прокрутка:** Автоматическое отслеживание активного файла во время синтеза и кнопка навигатора *"📍 К текущему файлу"* для мгновенного возврата к позициям обработки при ручной прокрутке списка.
* **📂 Умные пути (Smart Paths):** Программа запоминает последние открытые директории для каждого поля индивидуально. Если поле пустое, диалог вежливо откроет папку текущего проекта, что идеально для Portable-режима.
* **🎛️ Выборочный импорт/экспорт:** Окна с галочками для гибкого переноса отдельных групп параметров (папки, эффекты, API-лимиты) и правил глоссария (ударения, термины, RegEx) между проектами.
* **🔊 Умный плеер:** Повторный клик по кнопке *"🔊 Слушать"* мгновенно прерывает предыдущий трек без наслоения звука. Добавлена кнопка принудительной тишины `🔇`.
* **🛡️ Общий лимитер внутри экземпляра:** Пакетный и Прямой синтез в одном запущенном экземпляре Studio делят единый счётчик запросов. Разные процессы приложения не координируются между собой, поэтому их суммарная нагрузка и соответствие тарифному лимиту контролируются пользователем.
* **🧪 Песочница нормализатора (Новое в v1.5):** Отдельная вкладка показывает результат того же pipeline, который реально используется синтезом. Профили TTS/Safe, стадии `ru-normalizr`, глоссарий и preprocessing можно менять локально, сравнивать без API-запросов, экспортировать в JSON и только затем применять глобально.
* **🛡️ Verbatim и объединение глоссариев (Новое в v1.5):** Для термина или RegEx можно защитить точную замену от нормализации и финальной очистки. Импорт умеет объединять общий набор правил с личным глоссарием, по умолчанию не затирая существующие записи.
* **🎛 Аудиопрофили (Новое в v1.5):** Встроенные и пользовательские профили объединяют формат, битрейт, частоту, mono/stereo и эффекты. Их можно сохранять, импортировать/экспортировать и независимо применять к книжной сборке либо вкладке **«Экспорт и Сборка»**.
* **🧪 Экспериментальный Silero API Steps (Новое в v1.4.1):** Опциональная настройка скорости/качества EnhancedTTS с пресетами `4`, `8`, `12`, `16` и ручным диапазоном `1–72`. `16` используется как базовый ориентир качества; выше `16` показывается предупреждение, а заведомо отклоняемые API значения выше `72` не отправляются. По умолчанию поле отсутствует в payload, поэтому старые конфиги и прежнее поведение сохраняются.
* **Потоковая FFmpeg-склейка:** Фрагменты одной главы сшиваются через FFmpeg Concat Demuxer без загрузки всей главы в оперативную память. Разнородные MP3/WAV/OGG/Opus во вкладке **«Экспорт и Сборка»** также объединяются напрямую через FFmpeg с паузами, эффектами, тегами и поддерживаемой форматом обложкой, без общего PCM-буфера Pydub и промежуточного WAV. Поэтому длинные группы больше не упираются в 4-ГиБ предел обычного RIFF; при сохранении очень большого WAV автоматически используется RF64.
* **🏷️ In-Place Тегирование:** Режим *"Только обновить теги"* мгновенно перезаписывает метаданные прямо в оригинальных файлах **без перекодирования звука**; новые обложки записываются для MP3 и Opus. Отображение обложки Opus зависит от конкретного проигрывателя и его поддержки `METADATA_BLOCK_PICTURE`.
* **⏱️ Расчет Общего Времени:** В шапке дерева экспорта в реальном времени отображается точная суммарная длительность всех аудиофайлов проекта (`HH:MM:SS`).
* **⚙️ Массовое применение настроек групп:** Диалог *"Применить ко всем группам..."* позволяет в 1 клик скопировать параметры склейки, подпапок и пауз на все тома и сохранить их по умолчанию.
* **Атомарный кэш (Atomic Save):** Запись индекса через временные файлы и резервную копию снижает риск повреждения JSON при сбоях. Поддерживаются независимые режимы LRU (по количеству) и TTL (по времени жизни).
* **🎧 Компактный Ogg/Opus-кэш (Новое в v1.4.1):** Новые речевые фрагменты и паузы хранятся как Ogg/Opus 48 кГц mono с целевым битрейтом 48 кбит/с. Старый Vorbis можно в фоне, атомарно и с возможностью продолжения перекодировать отдельной кнопкой без изменения хэшей и привязки книги.
* **Постобработка звука:** Локальное изменение скорости (Tempo), тона (Pitch) и эха (Reverb) без повторной траты API-кредитов.
* **Сборщик книг и Экспорт:**
  * Поддержка одиночных файлов в Корне и древовидных Групп (Томов).
  * Кнопка **«🔗 Объединить»** собирает выбранные группы и/или одиночные файлы в одну группу. Первая группа по порядку дерева сохраняет имя, теги и настройки; итоговая группа занимает место первого выбранного источника, а содержимое располагается в текущем визуальном порядке. Остальные выбранные группы удаляются только из списка; если выбраны только файлы, создаётся новая группа. Группа, которую не выбирали целиком, намеренно остаётся даже после переноса всех отмеченных файлов, чтобы её настройки не исчезли без согласия. **«📤 Разгруппировать»** переносит дорожки выбранных групп на родительский уровень. **«🧹 Очистить всё»** очищает весь список после подтверждения. Эти операции меняют только проект и никогда не удаляют исходные аудиофайлы.
  * Основные настройки выбранной группы размещены компактной нативной сеткой без Canvas и полосы прокрутки. Флажки склейки и подпапки стоят рядом без растягивающего промежутка, а **«Применить ко всем группам…»** остаётся на отдельной строке. Текущие параметры аудиопрофиля вынесены в собственную строку под эффектами. Подпись статуса не имеет фиксированной ширины и использует короткие стадии **«Склейка»**, **«Экспорт»** и **«Теги»**. Если имя не помещается при текущих ширине окна и шрифте, оно получает многоточие в середине с сохранением начала и окончания; сокращается только временная подпись, а полное имя сохраняется в дереве без изменения. Индикатор прогресса занимает остаток строки. После подтверждённой остановки прогресс обнуляется, а рабочий статус возвращается к **«Ожидание...»**.
  * Человеческая натуральная сортировка (`Глава 2` всегда идет перед `Глава 10`).
  * Многопоточный фоновый импорт тысяч файлов с пакетным обновлением интерфейса без зависаний.
  * Авто-разбивка на тома работает и для файлов в корне, и для уже созданных групп; нумерация адаптивная (`1…9`, `01…10`, `001…100`). Новая группа учитывает уже видимую разрядность: после `01…10` создаётся `11`, а пропуск между `01` и `03` заполняется как `02`.
  * Во время активной сборки дерево, перегруппировка и настройки проекта блокируются; подпапка доступна только при экспорте группы отдельными файлами.
  * Перед стартом проверяются отсутствующие исходники и совпадающие выходные имена, чтобы один элемент не перезаписал другой.
  * Имена файлов/подпапок очищаются по общим правилам Windows, Linux и macOS; извлечение обложек и сетка 2х2 помогают массово переносить ID3-теги.
  * При склейке незаполненные поля ID3 группы наследуются от первого файла. Явно заданные значения группы имеют приоритет, а имя итогового файла и тег `Title` формируются из имени группы.
  * Параметры **«Битрейт»**, **«Частота»** и **«Каналы»** в компактной панели относятся к вкладке **«Экспорт и Сборка»**, сохраняются в настройках и одинаково применяются к одиночному файлу, несклеенной группе и общей дорожке. Режим **«Авто»** (`auto`) предсказуемо сохраняет исходные частоту, mono/stereo и известный общий битрейт одиночного файла или однородной группы: например, при конвертации однородных MP3 128 кбит/с в Opus целевым останется 128 кбит/с, поэтому результат не обязан быть меньше простой MP3-склейки. Для речевой книги с приоритетом размера следует явно выбрать Opus 48 кбит/с или пресет 32 кбит/с (с большей потерей качества), а не `Auto`. Для смешанной группы выбираются максимальная частота и stereo, если хотя бы один вход многоканальный; при неизвестном профиле безопасный fallback — 48 кГц stereo. Явные частота и каналы поддерживаются MP3, OGG, Opus и WAV и принудительно задают профиль результата в пределах возможностей кодека. Битрейт применяется только к сжатым MP3/OGG/Opus; для WAV PCM он неприменим и поле отключается. Очень большой WAV автоматически записывается как RF64. В `Auto` MP3 получает ближайшую частоту, поддерживаемую `libmp3lame` (не выше 48 кГц); явная неподдерживаемая частота не подменяется и вызывает понятную ошибку. OGG остаётся совместимым **Ogg/Vorbis (.ogg)**, а отдельный **Ogg/Opus (.opus)** создаёт тот же Ogg-контейнер с рекомендованным для Opus расширением. Поток с `.opus` при необходимости можно вручную переименовать в `.ogg` без перекодирования, но приложение намеренно не предлагает этот менее совместимый вариант. OGG/Vorbis сохраняет 88,2/96 кГц только при битрейте `Auto` в quality/VBR-режиме; Opus поддерживает 8/12/16/24/48 кГц. Некоторые сочетания низкой частоты, mono и высокого битрейта кодек физически не принимает: явный профиль блокируется с объяснением, а `Auto` сохраняет частоту и каналы, но не наследует несовместимый битрейт. Заданная пауза вставляется до общего эффекта скорости и поэтому изменяется вместе со всей дорожкой только один раз.
  * Финальный профиль синтезируемой книги настраивается независимо в **«Настройки → Вывод и Теги»** либо через менеджер аудиопрофилей. Его `Auto` для частоты и каналов означает внутренние 48 кГц mono, а не параметры файлов внешнего экспортного проекта.
* **Контроль CPU:** Настройка числа параллельных FFmpeg-кодирований — от автоматического использования доступных ресурсов до последовательной фоновой обработки.
* **🍏 Интеграция с буфером macOS:** Комбинации `⌘C`, `⌘V`, `⌘X`, `⌘A`, `⌘Z` обрабатываются при русской и английской раскладках; для копирования и вставки предусмотрен системный fallback через `pbcopy`/`pbpaste`. Физическое сочетание клавиш и стандартное событие Tk `<<Paste>>` сведены к одному обработчику с защитой от повтора, поэтому один жест вставляет фрагмент ровно один раз, в том числе в редактор глоссария. URL-кодирование декодируется только у явных путей Finder, поэтому пробелы и последовательности вроде `%20` в обычном тексте не изменяются.
* **🛡️ Кроссплатформенные улучшения:**
  * **Windows/Linux:** `Ctrl+C`, `Ctrl+V`, `Ctrl+X`, `Ctrl+A` и `Ctrl+Z` обрабатываются при русской и английской раскладках.
  * **Windows 11:** Автоматическая зачистка кавычек при вставке путей через *"Копировать как путь"*.
  * **Linux/macOS:** Декодирование явных локальных путей с префиксом `file://` или URL-последовательностями вроде `%20` без изменения обычного текста.
  * **NullWriter:** Защита Portable-версий от вылетов PyInstaller при сборках с флагом `--windowed` / `--noconsole`.

## 🧪 Экспериментальная настройка Steps

Настройка находится в **«Настройки → API и Лимиты»** сразу после поля **«Спикер (Голос)»**.

Официальный адрес по умолчанию использует HTTPS. Если пользователь вручную
задаёт другой API URL, приложение сохраняет и отправляет его без скрытой замены
протокола или endpoint, поэтому собственные серверы и прокси работают
предсказуемо.

| Режим | Поведение |
|---|---|
| Выключено (по умолчанию) | Поле `steps` отсутствует в API payload; Silero выбирает серверное значение по умолчанию. Это режим полной совместимости со старыми конфигами и прежним кэшем. |
| `4` | Ещё быстрее, но для большинства голосов качество заметно ухудшается. |
| `8` | Быстрее `16`, обычно с небольшим снижением качества. |
| `12` | Промежуточный экспериментальный вариант. |
| `16` | Базовый ориентир EnhancedTTS по качеству; медленнее `8`. |
| «Другое» | Целое число `1–72`. Для `17–31` требуется подтверждение из-за неопределённого выигрыша; при `32+` предупреждение усилено. Значения выше `72` блокируются до запроса, поскольку текущий endpoint отвечает HTTP 422. |

При включённом `steps` флажок **«Учитывать steps в ключе кэша»** становится доступным и по умолчанию включён: одинаковые текст и голос с разными значениями получают независимые записи. Пока сама экспериментальная опция выключена, флажок заблокирован, потому что учитывать нечего. Его можно сознательно снять ради общего legacy-ключа `текст + голос`; тогда одновременно хранится только один вариант, известное несовпадение вызывает новый API-запрос и заменяет общую запись.

Граница `72` отражает текущее фактическое поведение API: более высокие значения приложение не отправляет, чтобы избежать HTTP 422. Поскольку серверное поведение может измениться, настройка остаётся экспериментальной. В режиме «выключено» поле по-прежнему просто не передаётся.

### Совместимость и кэш

* У старых конфигов нет `api_steps_enabled`, поэтому `steps` не отправляется, а прежний MD5 `текст + голос` остаётся неизменным.
* Флажок **«Учитывать steps в ключе кэша»** доступен только при включённом `steps`; рекомендуемый режим — раздельные варианты.
* **«Оптимизировать кэш»** никогда не удаляет варианты качества молча. Если в индексе нет записей с явным `steps`, дополнительный выбор не показывается. Если они есть, окно выводит количество legacy- и Steps-записей и предлагает политику: при выключенном `steps` — сохранить все варианты либо оставить только legacy; при включённом раздельном ключе — сохранить всё, **legacy + текущий Steps** (рекомендуется) или только текущий Steps. В режиме общего legacy-ключа приложение отдельно предупреждает, что для одной фразы физически хранится только один вариант.
* В краткой таблице кэша колонка `steps` не показывается. Значение остаётся в подробной карточке по двойному клику, где оно нужно для диагностики происхождения записи.
* После оптимизации уже загруженная таблица обновляется автоматически, поэтому удалённые записи не остаются в ней «призраками». До первого ручного обновления вкладка по-прежнему не читает большой индекс с диска.
* Ручное **«Обновить»** читает большой индекс в рабочем потоке, а подготовка аудио из карточки кэша не блокирует интерфейс.
* В пределах одного запущенного экземпляра Studio архивация и перекодирование не запускаются одновременно с синтезом, оптимизацией или другой операцией кэша. Окно прогресса миграции не является модальным, поэтому по остальным вкладкам можно перемещаться. Межпроцессной блокировки каталога нет: не запускайте второй экземпляр приложения с той же папкой кэша, пока идёт его изменение. ZIP нельзя сохранить внутрь самой папки кэша. **«Очистить кэш после архивации»** сохраняет `glossary.json`, удаляя только аудиофрагменты, паузы и индекс.
* Имена аудиофайлов из `sentence_cache.json` проверяются перед прослушиванием и удалением и не могут выйти за пределы `cache/audio`.
* Ответ EnhancedTTS и локальные паузы используют единый внутренний формат **Ogg/Opus 48 кГц mono, 48 кбит/с**. Если автообрезка выключена и API уже вернул совместимый Opus, файл сохраняется байт-в-байт без повторного lossy-кодирования.
* При включённой автообрезке ответ проходит цепочку **Opus → PCM в памяти → Opus**: крайняя тишина удаляется, после чего фрагмент один раз кодируется обратно в Opus. WAV и промежуточного Vorbis в этом пути нет: PCM здесь является несжатым рабочим представлением Pydub, а не ещё одним файлом или lossy-кодеком. Vorbis поддерживается только для чтения и добровольной миграции старого кэша; для известного Ogg-кодека приложение передаёт декодер FFmpeg явно и не запускает отдельный `ffprobe`.
* Перед публикацией и финальной склейкой приложение читает только первые 4 КиБ каждого внутреннего `.ogg`, разбирает первую страницу контейнера и сверяет реальный идентификационный пакет `OpusHead`, а не доверяет одному полю `audio_codec` в JSON и не ищет маркер произвольно во всём заголовке. Проверка не запускает `ffprobe`, не декодирует звук и обычно незаметна на фоне FFmpeg/API; она защищает от повреждённых файлов, устаревших метаданных и случайного смешивания Vorbis/Opus.
* Кнопка **«Перекодировать Vorbis → Opus»** во вкладке кэша мигрирует старые речевые фрагменты из `cache/audio`, перечисленные в `sentence_cache.json`, в фоне. Имя `.ogg`, MD5-ключ и запись текста не меняются, поэтому существующая книга остаётся пригодна для полной пересборки. Каждый результат сначала создаётся во временном файле рядом с оригиналом и лишь затем заменяет его через `os.replace`; при ошибке старый Vorbis остаётся целым. Операцию можно остановить после уже запущенных файлов и повторить позднее — готовый Opus будет пропущен. Сами атомарно заменённые `.ogg` служат контрольными точками, а большой `sentence_cache.json` записывается один раз при завершении или штатной остановке, чтобы не создавать дисковый bottleneck.
* Каталог `cache/silences` массовым мигратором намеренно не сканируется. Старый файл паузы при первом использовании не пережимается из Vorbis, а заново создаётся как чистая тишина точно указанной длительности сразу в Opus и атомарно заменяет прежний файл. Настройки начала/конца, предложений, абзацев, реплик, двоеточий и разделителей при этом не теряются.
* Перекодирование старого речевого кэша добровольное и необратимое: Vorbis и Opus являются lossy-кодеками. На равномерной выборке **1024 реальных файлов** из кэша на 372 тыс. предложений переход на 48 кбит/с уменьшил логический размер на **34,5%**, а реально занятое APFS-место — на **33,1%**; фактический результат зависит от речи и исходного кодирования. Если миграцию не запускать заранее, **«Старт (Все)»** по исходным TXT безопасно преобразует в Opus каждый встретившийся старый Vorbis при первом cache-hit. Будут затронуты только реально используемые записи, а не весь каталог, поэтому для большого кэша предварительная фоновая миграция заметно быстрее первой полной пересборки.
* Число одновременных FFmpeg-процессов мигратора учитывает настройку **«Параллельных сборок FFmpeg»**; значение `0` автоматически использует до 24 однопоточных процессов в зависимости от числа CPU. Закрытие окна прогресса запрашивает штатную остановку после уже запущенных файлов, а не обрывает их.

## 🧪 Нормализатор, профили и verbatim

Вкладка **«Нормализатор»** предназначена для подготовки собственного профиля без синтеза и расхода API-лимитов. Слева редактируется небольшой исходный фрагмент и сразу показывается нормализованный результат; справа доступны публичные стадии `ru-normalizr 0.3.x`, режимы **TTS** и **Safe**, настройки инициалов, латинизации и пользовательских `.dic`. Начальная ширина текстовых полей уменьшена в пользу панели параметров, а границу всё равно можно перетянуть вручную. Размер шрифта обоих текстовых полей меняется в нижней панели и сохраняется вместе с общей настройкой интерфейса. Отдельными флажками можно отключить `ru-normalizr`, глоссарий и две стадии preprocessing Studio, что удобно для поиска ошибочного RegEx.

Изменения на этой вкладке локальны, пока не нажата кнопка **«Применить глобально»**. Постоянная строка состояния показывает сохранённый глобальный профиль и отдельно предупреждает о неприменённых локальных изменениях. Тот же сохранённый снимок и его краткая расшифровка видны в **«Настройки → Нормализация»**; оттуда можно сразу открыть песочницу. **«Вернуть глобальные»** отменяет эксперимент, а профиль нормализации можно импортировать или экспортировать отдельным JSON. В него не входят API Token, папки проекта и локальный абсолютный путь к каталогу словарей; при импорте локальный каталог получателя сохраняется. Переносимый профиль содержит полный снимок публичных опций и строго проверяется, поэтому опечатка не подменяется молча значением TTS/Safe. Предпросмотр использует те же подготовку текста, `sentenize`, глоссарий, нормализацию, очистку и фильтрацию неподдерживаемых чанков, что и синтез; поэтому он не является приблизительным вторым алгоритмом.

Кнопка **«Сохранить TXT…»** закреплена в постоянно видимой нижней панели и записывает завершённый предпросмотр как **UTF-8 без BOM**, чтобы его можно было править во внешнем редакторе ударений и повторно синтезировать без двойной нормализации. До первого успешного непустого preview кнопка видна, но отключена; любое изменение исходника, профиля или используемого JSON глоссария сразу инвалидирует старый результат и снова временно её отключает. Показанная в preview строка `[ПАУЗА РАЗДЕЛИТЕЛЯ]` записывается в TXT первым активным разделителем из текущих настроек. Если исходный абзац требовал `pause_speech`, но его начальный маркер исчез при обработке, в файле сохраняется структурный префикс `— `: при повторном запуске он включит паузу перед репликой, но не уйдёт в API.

Во вкладках **«Синтез из папки»** и **«Прямой синтез»** для такого TXT есть флажок **«Текст уже подготовлен»**. Он применяется к одному подтверждённому запуску, автоматически снимается после завершения и не пишется в `settings.json`. В этом режиме Studio обходит пользовательские RegEx, глоссарий, автообработку Studio, `ru-normalizr` и финальную очистку, но по-прежнему выполняет разбиение на чанки, ограничение `SAFE_LIMIT` и расстановку пауз. Чтобы паузы при повторном синтезе были эквивалентны, нужно сохранить тот же `synthesis_mode` и те же настройки пауз: сам TXT не хранит профиль нормализатора, режима синтеза или числовые паузы.

Если preview пропустил самостоятельные фрагменты без поддерживаемого текста, статус показывает их число, а **«Сохранить TXT…»** отдельно предупреждает, что в файл они не войдут, и запрашивает подтверждение.

Расширенное правило термина остаётся совместимым со старым форматом строк:

```json
{
  "terms_ignore_case": {
    "обычный термин": "обычная замена",
    "убого": {
      "replacement": "уб+о'го",
      "verbatim": true,
      "whole_word": true
    }
  }
}
```

`verbatim` означает, что **замена** вставляется после `ru-normalizr` и очистки и поэтому сохраняется точно, включая `+`, апострофы и другие нужные символы. Исходный термин сначала остаётся видим нормализатору: например, защита слова в `Глава IV` не мешает получить порядковое «четвёртая». Если сам исходник был изменён нормализатором и поздно локализовать его нельзя, Studio применяет резервную непрозрачную защиту и пишет `WARNING` с фрагментом текста; рядом с таким правилом согласование чисел или единиц может отличаться. Для обычных слов это редкий fallback, а для RegEx, захватывающего число, — ожидаемый компромисс string-only API.

По умолчанию `whole_word=true`: правило срабатывает только на целое слово. Совпадение внутри слова включается явно и защищает всё содержащее слово, чтобы служебная граница не добавила пробелы. `verbatim` доступен и RegEx-правилам; все последовательные совпадения внутри одного защищённого слова заменяются, как при обычном `re.sub`. Правила применяются после разбиения на предложения, поэтому такой RegEx не предназначен для захвата сразу нескольких предложений или строк.

**Импорт глоссария** теперь является merge-операцией. Можно выбрать ударения, термины и RegEx; при конфликте рекомендуется сохранить личное правило, а замена импортируемым включается отдельно. Порядок записей остаётся стабильным, итоговый диалог показывает число добавленных, заменённых, сохранённых и пропущенных дубликатов. Перед сохранением, preview, импортом и экспортом структура секций и синтаксис RegEx проверяются единообразно.

Кнопка **«Удалить правила…»** открывает отдельный менеджер с поиском и вкладками «Ударения», «Термины» и «RegEx». **«Выбрать результаты поиска»** отмечает только показанные фильтром строки текущего раздела, а **«Выбрать все в разделе»** — включая скрытые поиском. **«Снять всё в разделе»** снимает выбор и со скрытых строк текущего раздела; **«Очистить весь глоссарий…»** удаляет все известные секции правил. Удаление сначала меняет JSON в редакторе и попадает на диск только после **«Сохранить файл»**; неизвестные служебные поля будущих версий сохраняются. Закрытие приложения с такими правками предлагает сохранить, отбросить или отменить выход.

Редактор явно привязан к `glossary.json` текущей папки кэша. При смене `cache_dir` чистый редактор автоматически загружает новый файл; несохранённые изменения не переносятся в него молча. Ручная **«Перезагрузка»** также требует подтверждения. Повреждённый primary не скрывает исправный `.bak`, а если обе копии невалидны, текущий текст редактора остаётся нетронутым. Пока конфликт не разрешён, устаревший preview нельзя сохранить и старый JSON нельзя случайно записать поверх глоссария нового кэша. Перед обычным пакетным или прямым синтезом Studio предлагает записать несохранённый глоссарий, если его правила уже участвовали в preview, но ещё не попали на диск. Режим **«Текст уже подготовлен»** закономерно обходит эту проверку вместе со всем глоссарием.

Если для одного слова одновременно существуют правило ударения и правило термина в том же режиме регистра, для совместимости побеждает термин. Оба правила остаются в JSON, но Studio показывает предупреждение, пишет его в журнал и помечает неактивное ударение в менеджере — конфликт больше не выглядит как случайно потерянное правило.

## 🎛 Аудиопрофили

Менеджер открывается кнопкой **«Аудиопрофили…»** рядом с форматом во вкладке **«Экспорт и Сборка»** либо из **«Настройки → Вывод и Теги»**. Профиль содержит формат MP3/WAV/OGG/Opus, битрейт, частоту, каналы и эффекты. Встроены варианты Opus 32/48 кбит/с, MP3 128 кбит/с, OGG/Vorbis Auto и WAV; любой текущий профиль книги или экспорта можно загрузить в редактор, сохранить под своим именем и перенести отдельным JSON. Кнопки **«Добавить»**, **«Сохранить профиль»**, **«Удалить»** и импорт сначала меняют временную копию списка. Текущие поля автоматически попадают в этот список при **«Сохранить и закрыть»** или применении; перед переключением с несохранённых полей менеджер предлагает сохранить, отбросить либо продолжить редактирование. **«Отмена»**, Escape и закрытие окна отбрасывают изменения. Кнопки применения сохраняют ту же версию профиля, применяют её только к указанной области и закрывают окно. Действия применения и сохранения разнесены по отдельным рядам, поэтому commit-кнопка не скрывается при масштабировании интерфейса. Экспорт JSON является отдельной записью внешнего файла и, естественно, не удаляется кнопкой «Отмена».

Профиль является шаблоном: применение копирует и заменяет текущие параметры выбранной области, но не создаёт скрытой постоянной связи. Поэтому интерфейс показывает краткую расшифровку текущих параметров и имя профиля только при точном совпадении; после ручной правки отображаются **«Пользовательские параметры»**.

**«К экспорту»** меняет только универсальный сборщик и его локальные эффекты. **«К сборке книги»** не затрагивает экспорт, но заменяет текущие значения в **«Настройки → Эффекты (Постобработка)»** и стартовые значения Прямого синтеза: в ветке 1.x у них общий финальный вывод. После применения всегда побеждает последняя явная ручная правка; она не переписывает сохранённый профиль. Локальные ползунки Прямого синтеза применяются только к его текущему запуску, пока пользователь отдельно не нажмёт **«Сделать глобальными»**. Начиная с v1.5 формат универсального экспорта хранится отдельно; при чтении старого `settings.json` или выборочном импорте старого профиля прежний общий формат копируется в обе области. Для книжной сборки `Auto` по частоте и каналам детерминированно означает канонический профиль кэша **48 кГц mono**. Явные значения передаются FFmpeg через `-ar/-ac` и проверяются на совместимость с кодеком. Явный битрейт применяется и к книжному OGG/Vorbis; `Auto` означает 128 кбит/с для MP3, 48 кбит/с для Opus, штатный quality/VBR-режим Vorbis и отсутствие битрейта у WAV. Для внешнего экспорта `Auto` сохраняет общий битрейт однородных совместимых входов; для смешанного, неизвестного или несовместимого набора выбирается безопасная политика целевого кодека. Скрытой гарантии уменьшения размера нет.

Флажок **«Включить эффекты в профиле»** является частью шаблона. Если он выключен, применение профиля даёт чистый звук: для книги/Прямого синтеза скорость и тон возвращаются к `1.0`, эхо отключается; для экспорта отключается общий флажок **«Наложить эффекты»**. Числовые значения в редакторе профиля при этом сохраняются и снова используются, если флажок включить.

### Прямой синтез

Флажок **«Применить теги из настроек»** по умолчанию выключен и намеренно не
запоминается между запусками приложения. Поэтому тестовый `direct_output` не
получает книжные title/artist/album и обложку без явного выбора пользователя в
текущем сеансе. Пакетный синтез сохраняет прежнее поведение.

Прямой синтез сохраняет файлы в отдельную настраиваемую папку
`direct_audio` (поле **«Папка»** на самой вкладке). В
**«Настройки → Папки»** отдельное дублирующее поле не показывается: путь всё
равно входит в группу **«Пути к папкам»** при импорте/экспорте профиля. Поэтому
тестовые результаты не смешиваются с главами пакетного синтеза.

Пустой ввод и текст, состоящий только из пунктуации, не создают фиктивный
аудиофайл из начальной/конечной паузы и получают понятный статус **«Нет
текста»**. Для намеренного файла тишины используйте настроенную строку-
разделитель. Разделитель распознаётся только тогда, когда занимает целую строку;
кроме него допускаются лишь пробелы и табуляции. Варианты вроде `---` и `–––`
защищаются до нормализации тире и не превращаются в начало диалога.
Во время обработки распознанной строки прогресс явно показывает
`[ПАУЗА РАЗДЕЛИТЕЛЯ]`, чтобы намеренная тишина не выглядела зависанием.
Две или несколько строк-разделителей подряд не схлопываются: каждая добавляет
полную настроенную паузу. С правилом максимума объединяется только структурная
пауза на границе последнего разделителя и следующего обычного абзаца; сами
последовательные разделители остаются отдельными.
Обычный минус перед количественным числом сохраняется слитно и через пробел
(`-5`, `- 5`), а
Unicode-минус приводится к понятному нормализатору дефису (`−5` → `-5`).
Короткое и длинное тире в начале строки по-прежнему считаются маркерами
реплики. В начале отдельной строки дефис перед порядковым числительным
(`- 62-й ранг`) также считается тире реплики, а не отрицательным числом.

На границе абзацев паузы не складываются. Обычная пауза между абзацами,
увеличенная пауза перед репликой/отдельной мыслью в одинарных или двойных
кавычках, пауза после двоеточия и соседняя пауза строки-разделителя сравниваются,
после чего вставляется одно наибольшее значение. Двоеточие распознаётся также
перед закрывающей кавычкой или скобкой, поэтому конструкция
`«Он подумал:»` корректно увеличивает паузу перед следующим абзацем.
Точные числовые паузы между абзацами применяются в режимах `sentence` и
`paragraph`. В режиме `full` абзацы входят в один большой запрос, поэтому их
внутренний ритм определяет модель по переводам строк; правило максимума всё
равно действует на явных строках-разделителях и защитных разрывах `SAFE_LIMIT`.

Программа не вводит дополнительную агрессивную очистку всей пунктуации в
начале фразы: это позволяет не повредить знаки чисел, формулы и ручные
ударения. Существующая очистка служебных символов и начального тире реплики
сохраняется.

Текстовые метаданные экспорта, включая название, исполнителя, альбом,
исполнителя альбома, жанр, композитора и год, записываются и в Ogg/Opus. Обложка
JPEG/PNG для MP3 встраивается как совместимый ID3v2.3/APIC. Для Opus она
хранится штатно в комментарии `METADATA_BLOCK_PICTURE`, а не как неподдерживаемый
JPEG/PNG-видеопоток `attached_pic`; комментарий передаётся FFmpeg через
временный metadata-файл, поэтому размер изображения не упирается в лимит длины
командной строки. Отдельный `opusenc` для этого не требуется. Некоторые
проигрыватели Windows и старые медиакаталоги этот комментарий не показывают,
хотя он остаётся записанным в файле.
Ogg/Vorbis и WAV по-прежнему не принимают картинку этим способом и безопасно
пропускают её с записью в журнал вместо ошибки всей сборки.

### Импорт и экспорт конфигурации

Профиль разделён на независимые группы: API и лимиты, пути, паузы, кэш,
нормализатор, эффекты, **«Вывод, аудиопрофили и Теги»** и значения вкладок. Если группа путей выключена, чужие
папки не импортируются. История файловых диалогов и размер шрифта являются
локальными предпочтениями и в профиль не входят. API Token считается секретом:
его импорт и экспорт требуют отдельной выключенной по умолчанию галочки.
Импорт всей группы вывода заменяет переносимый список пользовательских аудиопрофилей;
для добавления ровно одного профиля с проверкой совпадающего имени используйте
отдельный импорт в менеджере **«Аудиопрофили…»**.

Импорт и сброс настроек, применение глобального профиля нормализатора и commit
аудиопрофилей сначала атомарно записывают подготовленный снимок и только затем
меняют работающий интерфейс. Ошибка доступа к диску поэтому не выдаётся за
успех и не оставляет временные значения активными только до перезапуска.
Повреждённый `settings.json` восстанавливается из `.bak`; повреждённый primary-
файл при следующем save не может затереть исправную резервную копию.

## ⚙️ Установка и запуск

Ниже описан запуск **из исходников**. Основная и рекомендуемая ветка — **Python 3.13**; **Python 3.12** сохраняется как проверенный legacy-вариант. Python 3.14 и версии 3.11 и старше в текущую тестируемую матрицу не входят. Также нужны Tkinter и системные **FFmpeg/FFprobe**. Прямые Python-зависимости зафиксированы в `requirements.txt`. На Python 3.13 автоматически устанавливается `audioop-lts`, потому что модуль `audioop` удалён из стандартной библиотеки; Python 3.12 использует встроенный `audioop`. Готовые полные сборки уже содержат FFmpeg/FFprobe. Официальные Windows/Linux-артефакты собираются в GitHub Actions на **Python 3.13.15**, а macOS-артефакты — на актуальном Homebrew Python **3.13.x** с Tcl/Tk 9.0.x; во всех случаях используется полностью зафиксированный `requirements-release.txt`.

### Шаг 1. Установка FFmpeg/FFprobe для исходников и Portable-сборок

Этот шаг можно пропустить для полной Windows-версии в ZIP, полных Linux-версий в ZIP и macOS `.app`.
Системная сборка FFmpeg должна содержать кодировщики `libopus` и `libvorbis`;
обычные актуальные пакеты ниже их включают. GitHub Actions отдельно проверяет
эти кодеки перед упаковкой полных артефактов.

* **Windows:**
  1. Скачайте архив с FFmpeg (например, с [gyan.dev](https://www.gyan.dev/ffmpeg/builds/)).
  2. Распакуйте его в удобное место (например, `C:\ffmpeg`).
  3. Добавьте путь к папке `bin` (например, `C:\ffmpeg\bin`) в системные переменные среды `PATH`.
* **macOS:**
  Установите FFmpeg с поддержкой Opus/Vorbis через Homebrew:
  ```bash
  brew tap homebrew-ffmpeg/ffmpeg
  brew install homebrew-ffmpeg/ffmpeg/ffmpeg
  ```
* **Linux (Ubuntu/Debian):**
  ```bash
  sudo apt update && sudo apt install ffmpeg
  ```

### Шаг 2. Установка зависимостей Python

Рекомендуется устанавливать зависимости в отдельное виртуальное окружение. На macOS/Linux:
```bash
python3.13 -m venv .venv313
source .venv313/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip check
```
На Windows:
```powershell
py -3.13 -m venv .venv313
.venv313\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip check
```
Для legacy-запуска на Python 3.12 замените `python3.13` / `py -3.13` на 3.12 и используйте отдельное окружение, например `.venv312`. Важно запускать `pip` через тот же Python, которым затем запускается приложение. `audioop-lts` устанавливается только для Python 3.13; на Python 3.12 используется модуль стандартной библиотеки.

Команда `python3.13 SileroTTS_Studio.py` использует глобальное окружение Python 3.13, а не созданное выше виртуальное окружение. Поэтому ошибка `ModuleNotFoundError: No module named 'requests'` означает, что зависимости установлены не в тот интерпретатор. Предпочтительный запуск — после `source .venv313/bin/activate` командой `python SileroTTS_Studio.py` либо напрямую:
```bash
.venv313/bin/python SileroTTS_Studio.py
```

`requirements-release.txt` предназначен для воспроизводимой сборки готовых артефактов и фиксирует также транзитивные библиотеки и PyInstaller. ОС-зависимые пакеты PyInstaller перечислены с маркерами платформы, поэтому один файл подходит Windows, Linux и macOS. Для обычного запуска из исходников используйте `requirements.txt`; для локального повторения окружения GitHub Actions на Python 3.13 можно выполнить:
```bash
python3.13 -m venv .venv-release
source .venv-release/bin/activate
python -m pip install -r requirements-release.txt
```

Проверить Tkinter можно командой:
```bash
python -m tkinter
```
Официальные сборки Python с python.org обычно уже содержат Tkinter. Для Homebrew Python 3.13 установите соответствующий пакет Tk:
```bash
brew install python-tk@3.13
```
На macOS проверенная и рекомендуемая связка — **Python 3.13.x + Tcl/Tk 9.0.x** (локально проверены Python 3.13.15 и Tk 9.0.4). Она нужна не для основных функций синтеза, а для надёжного обновления уже открытого Aqua-интерфейса при переключении системной светлой/тёмной темы. Python 3.12 и Tk 8.6 по-прежнему поддерживаются: если оформление не обновилось на лету, перезапустите приложение после смены системной темы. Homebrew предоставляет актуальный patch-релиз ветки 3.13, поэтому CI проверяет ветку Python 3.13, фактическую patch-версию внутри `.app` и Tk 9.0.x, а не требует от Homebrew исторический patch 3.13.15. Для Windows и Linux Tk 9 не является требованием; штатный Tk 8.6 поддерживается. Для Linux установите Tkinter командой `sudo apt install python3-tk`.

### Шаг 3. Запуск

В активированном окружении:
```bash
python SileroTTS_Studio.py
```
Без активации окружения на macOS/Linux:
```bash
.venv313/bin/python SileroTTS_Studio.py
```

## 🖥 Особенности работы на разных ОС

* **macOS (.app & .py):** Из-за ограничений безопасности Apple (Gatekeeper) скомпилированное приложение создаёт структуру проекта в `~/Documents/SileroTTS_Studio/`. Поддерживаются нативные горячие клавиши `⌘C`, `⌘V`, `⌘X`, `⌘A`, `⌘Z`, атомарный мультивыбор мышкой через `⌘-Click` и контрастные статусные палитры для светлого/тёмного оформления. Системные сообщения привязаны к главному окну и после закрытия возвращают локальный фокус прежнему полю без принудительного перехвата фокуса у другого приложения. Любой пользовательский клик внутри главного окна повторно подтверждает его локальный фокус; события `Activate/Deactivate` отслеживают нативную активность, а старт и повторная активация переустанавливают текущую ttk-тему и инвалидируют Aqua-виджеты. Поэтому прогрессбары и ползунки не должны оставаться серыми, но дорогостоящая перерисовка не выполняется на каждом клике уже активного окна. Статус «Ожидание» относится к информационному цвету: тёмно-синему в светлой теме и небесно-голубому в тёмной. Дочерние FFmpeg/FFprobe запускаются без небезопасного `fork` после инициализации Tk/CoreFoundation, поэтому параллельная сборка не должна выводить системное предупреждение `You MUST exec()`. Готовая `.app` уже содержит FFmpeg/FFprobe.
* **Windows:** Бесшумная работа фоновых утилит — окна командной строки не моргают при генерации и сборке (`CREATE_NO_WINDOW`). Полная версия поставляется папкой в ZIP и содержит FFmpeg/FFprobe; Portable-версия поставляется одним `.exe` и использует системные FFmpeg/FFprobe.
* **Linux:** Полная версия поставляется папкой в ZIP и содержит FFmpeg/FFprobe; Portable `onefile` поставляется в ZIP и использует системные FFmpeg/FFprobe.
* **Portable-режим:** При запуске `.py` из консоли на любой ОС, Windows Portable `.exe` или Linux Portable-бинарника рабочие папки создаются рядом с запущенным файлом. Для работы со звуком FFmpeg/FFprobe должны быть доступны в `PATH`.

## Диагностика частичного результата

Если итоговый MP3 создан, но получил статус **«Предупреждение»**, это означает,
что сборка формата завершилась, однако один или несколько речевых фрагментов
были заменены паузой после неудачных повторных попыток. В логе ищите исходную
причину (`HTTP 429`, ошибка API или ошибка локального декодирования), а не только
сообщение о сохранении MP3. На macOS при запуске из IDE/Finder приложение
использует абсолютные пути к встроенным или Homebrew `ffmpeg`/`ffprobe`, поэтому
урезанный `PATH` больше не должен приводить к сообщению `No such file or directory: 'ffprobe'`. Для Portable-сборок Windows/Linux системные бинарники по-прежнему
должны быть доступны в `PATH`.

Имена и содержимое файлов кэша вычисляются в UTF-8. Начальный BOM в корректном
UTF-8 TXT считается служебной сигнатурой кодировки и бесшумно удаляется до
пользовательских RegEx и вычисления ключа кэша; внутренние `U+FEFF` не
вычищаются. Поэтому один и тот же файл с BOM и без него получает одинаковые
нормализованные фразы. После нормализации
самостоятельный чанк, в котором нет ни русских, ни ASCII-букв, не
отправляется: EnhancedTTS считает состоящий только из неподдерживаемых символов
фрагмент пустым и отвечает `HTTP 422: Your text is empty!`. Unicode-символы
внутри обычной поддерживаемой фразы не вычищаются, поэтому её payload и
существующий MD5-ключ кэша не меняются. Ожидаемый пропуск записывается в лог на
уровне `INFO`; ответы HTTP/API и локальные ошибки содержат короткие поля
`source` и `normalized`, а HTTP 422 дополнительно показывает безопасный
`detail` сервера и не повторяется пять раз. Цифры штатно превращаются
`ru-normalizr` в слова; если библиотека недоступна, отдельный чанк только из
цифр также пропускается вместо заведомого 422.
