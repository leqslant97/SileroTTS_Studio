# 🎙 Silero TTS Studio

Профессиональная рабочая среда (GUI) для генерации аудиокниг, подкастов и озвучки текста с использованием нейросети Silero.

Программа оптимизирована для создания длинных аудиокниг с минимальными затратами API-лимитов. Поддерживает молниеносное O(1) RAM-кэширование, локальную постобработку звука (FFmpeg), работу с глоссариями, извлечение текста из электронных книг (EPUB, FB2, DOCX) и пакетную сборку с редактированием ID3-тегов.

---

## 🚀 Основные возможности

* **⚡ Мощный O(1) RAM-кэш (Новое в v1.4):** Революционная архитектура работы с кэшем в оперативной памяти без блокировки жесткого диска. Сборка готовой книги на сотни часов из кэша занимает считанные минуты, задействуя 100% ресурсов процессора для параллельного рендера FFmpeg.
* **📖 Умный HTML-парсер книг (Новое в v1.4):** Алгоритм очистки текста при импорте из EPUB и FB2 больше не разрывает абзацы из-за внутренних тегов `<br/>`, `<em>`, `<strong>` или оформления кода.
* **📍 Навигатор и авто-прокрутка (Новое в v1.4):** Автоматическое отслеживание активного файла во время синтеза и кнопка навигатора *"📍 К текущему файлу"* для мгновенного возврата к позициям обработки при ручной прокрутке списка.
* **📂 Умные пути (Smart Paths) (Новое в v1.4):** Программа запоминает последние открытые директории для каждого поля индивидуально. Если поле пустое, диалог вежливо откроет папку текущего проекта, что идеально для Portable-режима.
* **🎛️ Выборочный импорт/экспорт (Новое в v1.4):** Окна с галочками для гибкого переноса отдельных групп параметров (папки, эффекты, API-лимиты) и правил глоссария (ударения, термины, RegEx) между проектами.
* **🔊 Умный плеер (Новое в v1.4):** Повторный клик по кнопке *"🔊 Слушать"* мгновенно прерывает предыдущий трек без наслоения звука. Добавлена кнопка принудительной тишины `🔇`.
* **🛡️ Глобальный синхронный лимитер (Новое в v1.4):** Единый лимитер частоты запросов защищает API-токен от блокировок при одновременной работе прямого синтеза и обработки папки.
* **🧪 Экспериментальный Silero API Steps (Новое в v1.4.1):** Опциональная настройка скорости/качества EnhancedTTS с пресетами `4`, `8`, `12`, `16` и ручным диапазоном `1–72`. `16` используется как базовый ориентир качества; выше `16` показывается предупреждение, а заведомо отклоняемые API значения выше `72` не отправляются. По умолчанию поле отсутствует в payload, поэтому старые конфиги и прежнее поведение сохраняются.
* **FFmpeg Concat для результатов синтеза:** Фрагменты одной главы сшиваются через FFmpeg Concat Demuxer без загрузки всей главы в оперативную память. Отдельная склейка разнородных MP3/WAV/OGG во вкладке **«Экспорт и Сборка»** использует Pydub/AudioSegment, поскольку там одновременно поддерживаются перекодирование, паузы, эффекты, теги и обложки; для очень больших объединяемых групп ей требуется соответствующий запас RAM.
* **🏷️ In-Place Тегирование:** Режим *"Только обновить теги"* мгновенно перезаписывает метаданные и вшивает обложки прямо в оригинальные файлы на диске **без перекодирования звука** и с нулевой потерей качества.
* **⏱️ Расчет Общего Времени:** В шапке дерева экспорта в реальном времени отображается точная суммарная длительность всех аудиофайлов проекта (`HH:MM:SS`).
* **⚙️ Массовое применение настроек групп:** Диалог *"Применить ко всем группам..."* позволяет в 1 клик скопировать параметры склейки, подпапок и пауз на все тома и сохранить их по умолчанию.
* **Атомарный кэш (Atomic Save):** Запись индекса во временные файлы исключает повреждение JSON при сбоях. Поддерживаются независимые режимы LRU (по количеству) и TTL (по времени жизни).
* **🎧 Компактный Ogg/Opus-кэш (Новое в v1.4.1):** Новые речевые фрагменты и паузы хранятся как Ogg/Opus 48 кГц mono с целевым битрейтом 48 кбит/с. Старый Vorbis можно в фоне, атомарно и с возможностью продолжения перекодировать отдельной кнопкой без изменения хэшей и привязки книги.
* **Постобработка звука:** Локальное изменение скорости (Tempo), тона (Pitch) и эха (Reverb) без повторной траты API-кредитов.
* **Сборщик книг и Экспорт:**
  * Поддержка одиночных файлов в Корне и древовидных Групп (Томов).
  * Человеческая натуральная сортировка (`Глава 2` всегда идет перед `Глава 10`).
  * Многопоточный фоновый импорт тысяч файлов с пакетным обновлением интерфейса без зависаний.
  * Авто-разбивка на тома работает и для файлов в корне, и для уже созданных групп; нумерация адаптивная (`1…9`, `01…10`, `001…100`).
  * Во время активной сборки дерево, перегруппировка и настройки проекта блокируются; подпапка доступна только при экспорте группы отдельными файлами.
  * Перед стартом проверяются отсутствующие исходники и совпадающие выходные имена, чтобы один элемент не перезаписал другой.
  * Имена файлов/подпапок очищаются по общим правилам Windows, Linux и macOS; извлечение обложек и сетка 2х2 помогают массово переносить ID3-теги.
  * При склейке незаполненные поля ID3 группы наследуются от первого файла. Явно заданные значения группы имеют приоритет, а имя итогового файла и тег `Title` формируются из имени группы.
* **Контроль CPU:** Настройка параллельных потоков кодирования (от максимальной скорости до "тихого/холодного" фонового режима для ноутбуков).
* **🍏 Интеграция с буфером macOS:** Комбинации `⌘C`, `⌘V`, `⌘X`, `⌘A`, `⌘Z` обрабатываются при русской и английской раскладках; для копирования и вставки предусмотрен системный fallback через `pbcopy`/`pbpaste`. URL-кодирование декодируется только у явных путей Finder, поэтому пробелы и последовательности вроде `%20` в обычном тексте не изменяются.
* **🛡️ Пуленепробиваемая кроссплатформенность:**
  * **Windows 11:** Автоматическая зачистка кавычек при вставке путей через *"Копировать как путь"*.
  * **Linux/macOS:** Декодирование явных локальных путей с префиксом `file://` или URL-последовательностями вроде `%20` без изменения обычного текста.
  * **NullWriter:** Защита Portable-версий от вылетов PyInstaller при сборках с флагом `--windowed` / `--noconsole`.

## 🧪 Экспериментальная настройка Steps

Настройка находится в **«Настройки → API и Лимиты»** сразу после поля **«Спикер (Голос)»**.

Официальный адрес по умолчанию использует HTTPS. Если пользователь вручную
задаёт другой API URL, приложение сохраняет и отправляет его без скрытой замены
протокола или endpoint, поэтому собственные серверы и прокси работают
предсказуемо.

| Режим | Поведение |
|---|---|
| Выключено (по умолчанию) | Поле `steps` отсутствует в API payload; Silero выбирает серверное значение по умолчанию. Это режим полной совместимости со старыми конфигами и прежним кэшем. |
| `4` | Ещё быстрее, но для большинства голосов качество заметно ухудшается. |
| `8` | Быстрее `16`, обычно с небольшим снижением качества. |
| `12` | Промежуточный экспериментальный вариант. |
| `16` | Базовый ориентир EnhancedTTS по качеству; медленнее `8`. |
| «Другое» | Целое число `1–72`. Для `17–31` требуется подтверждение из-за неопределённого выигрыша; при `32+` предупреждение усилено. Значения выше `72` блокируются до запроса, поскольку текущий endpoint отвечает HTTP 422. |

При включённом `steps` флажок **«Учитывать steps в ключе кэша»** становится доступным и по умолчанию включён: одинаковые текст и голос с разными значениями получают независимые записи. Пока сама экспериментальная опция выключена, флажок заблокирован, потому что учитывать нечего. Его можно сознательно снять ради общего legacy-ключа `текст + голос`; тогда одновременно хранится только один вариант, известное несовпадение вызывает новый API-запрос и заменяет общую запись.

Граница `72` отражает текущее фактическое поведение API: более высокие значения приложение не отправляет, чтобы избежать HTTP 422. Поскольку серверное поведение может измениться, настройка остаётся экспериментальной. В режиме «выключено» поле по-прежнему просто не передаётся.

Параметр `emotion` в ветке 1.x намеренно не добавлен в API, интерфейс или
конфиг: поддержка зависит от голоса, а для целой аудиокниги без редактора сцен
и реплик это создаёт больше неоднозначности и дробления кэша, чем пользы.

### Совместимость и кэш

* У старых конфигов нет `api_steps_enabled`, поэтому `steps` не отправляется, а прежний MD5 `текст + голос` остаётся неизменным.
* Флажок **«Учитывать steps в ключе кэша»** доступен только при включённом `steps`; рекомендуемый режим — раздельные варианты.
* **«Оптимизировать кэш»** никогда не удаляет варианты качества молча. Если в индексе нет записей с явным `steps`, дополнительный выбор не показывается. Если они есть, окно выводит количество legacy- и Steps-записей и предлагает политику: при выключенном `steps` — сохранить все варианты либо оставить только legacy; при включённом раздельном ключе — сохранить всё, **legacy + текущий Steps** (рекомендуется) или только текущий Steps. В режиме общего legacy-ключа приложение отдельно предупреждает, что для одной фразы физически хранится только один вариант.
* В краткой таблице кэша колонка `steps` не показывается. Значение остаётся в подробной карточке по двойному клику, где оно нужно для диагностики происхождения записи.
* После оптимизации уже загруженная таблица обновляется автоматически, поэтому удалённые записи не остаются в ней «призраками». До первого ручного обновления вкладка по-прежнему не читает большой индекс с диска.
* Ручное **«Обновить»** читает большой индекс в рабочем потоке, а подготовка аудио из карточки кэша не блокирует интерфейс.
* В пределах одного запущенного экземпляра Studio архивация и перекодирование не запускаются одновременно с синтезом, оптимизацией или другой операцией кэша. Окно прогресса миграции не является модальным, поэтому по остальным вкладкам можно перемещаться. Межпроцессной блокировки каталога нет: не запускайте второй экземпляр приложения с той же папкой кэша, пока идёт его изменение. ZIP нельзя сохранить внутрь самой папки кэша. **«Очистить кэш после архивации»** сохраняет `glossary.json`, удаляя только аудиофрагменты, паузы и индекс.
* Имена аудиофайлов из `sentence_cache.json` проверяются перед прослушиванием и удалением и не могут выйти за пределы `cache/audio`.
* Ответ EnhancedTTS и локальные паузы используют единый внутренний формат **Ogg/Opus 48 кГц mono, 48 кбит/с**. Если автообрезка выключена и API уже вернул совместимый Opus, файл сохраняется байт-в-байт без повторного lossy-кодирования.
* При включённой автообрезке ответ проходит цепочку **Opus → PCM в памяти → Opus**: крайняя тишина удаляется, после чего фрагмент один раз кодируется обратно в Opus. WAV и промежуточного Vorbis в этом пути нет: PCM здесь является несжатым рабочим представлением Pydub, а не ещё одним файлом или lossy-кодеком. Vorbis поддерживается только для чтения и добровольной миграции старого кэша; для известного Ogg-кодека приложение передаёт декодер FFmpeg явно и не запускает отдельный `ffprobe`.
* Перед публикацией и финальной склейкой приложение читает только первые 4 КиБ каждого внутреннего `.ogg`, разбирает первую страницу контейнера и сверяет реальный идентификационный пакет `OpusHead`, а не доверяет одному полю `audio_codec` в JSON и не ищет маркер произвольно во всём заголовке. Проверка не запускает `ffprobe`, не декодирует звук и обычно незаметна на фоне FFmpeg/API; она защищает от повреждённых файлов, устаревших метаданных и случайного смешивания Vorbis/Opus.
* Кнопка **«Перекодировать Vorbis → Opus»** во вкладке кэша мигрирует старые речевые фрагменты из `cache/audio`, перечисленные в `sentence_cache.json`, в фоне. Имя `.ogg`, MD5-ключ и запись текста не меняются, поэтому существующая книга остаётся пригодна для полной пересборки. Каждый результат сначала создаётся во временном файле рядом с оригиналом и лишь затем заменяет его через `os.replace`; при ошибке старый Vorbis остаётся целым. Операцию можно остановить после уже запущенных файлов и повторить позднее — готовый Opus будет пропущен. Сами атомарно заменённые `.ogg` служат контрольными точками, а большой `sentence_cache.json` записывается один раз при завершении или штатной остановке, чтобы не создавать дисковый bottleneck.
* Каталог `cache/silences` массовым мигратором намеренно не сканируется. Старый файл паузы при первом использовании не пережимается из Vorbis, а заново создаётся как чистая тишина точно указанной длительности сразу в Opus и атомарно заменяет прежний файл. Настройки начала/конца, предложений, абзацев, реплик, двоеточий и разделителей при этом не теряются.
* Перекодирование старого речевого кэша добровольное и необратимое: Vorbis и Opus являются lossy-кодеками. На равномерной выборке **1024 реальных файлов** из кэша на 372 тыс. предложений переход на 48 кбит/с уменьшил логический размер на **34,5%**, а реально занятое APFS-место — на **33,1%**; фактический результат зависит от речи и исходного кодирования. Если миграцию не запускать заранее, **«Старт (Все)»** по исходным TXT безопасно преобразует в Opus каждый встретившийся старый Vorbis при первом cache-hit. Будут затронуты только реально используемые записи, а не весь каталог, поэтому для большого кэша предварительная фоновая миграция заметно быстрее первой полной пересборки.
* Число одновременных FFmpeg-процессов мигратора учитывает настройку **«Параллельных сборок FFmpeg»**; значение `0` автоматически использует до 24 однопоточных процессов в зависимости от числа CPU. Закрытие окна прогресса запрашивает штатную остановку после уже запущенных файлов, а не обрывает их.

### Прямой синтез

Флажок **«Применить теги из настроек»** по умолчанию выключен и намеренно не
запоминается между запусками приложения. Поэтому тестовый `direct_output` не
получает книжные title/artist/album и обложку без явного выбора пользователя в
текущем сеансе. Пакетный синтез сохраняет прежнее поведение.

Прямой синтез сохраняет файлы в отдельную настраиваемую папку
`direct_audio` (поле **«Папка»** на самой вкладке). В
**«Настройки → Папки»** отдельное дублирующее поле не показывается: путь всё
равно входит в группу **«Пути к папкам»** при импорте/экспорте профиля. Поэтому
тестовые результаты не смешиваются с главами пакетного синтеза.

Пустой ввод и текст, состоящий только из пунктуации, не создают фиктивный
аудиофайл из начальной/конечной паузы и получают понятный статус **«Нет
текста»**. Для намеренного файла тишины используйте настроенную строку-
разделитель. Разделитель распознаётся только тогда, когда занимает целую строку;
кроме него допускаются лишь пробелы и табуляции. Варианты вроде `---` и `–––`
защищаются до нормализации тире и не превращаются в начало диалога.
Во время обработки распознанной строки прогресс явно показывает
`[ПАУЗА РАЗДЕЛИТЕЛЯ]`, чтобы намеренная тишина не выглядела зависанием.
Две или несколько строк-разделителей подряд не схлопываются: каждая добавляет
полную настроенную паузу. С правилом максимума объединяется только структурная
пауза на границе последнего разделителя и следующего обычного абзаца; сами
последовательные разделители остаются отдельными.
Обычный минус перед количественным числом сохраняется слитно и через пробел
(`-5`, `- 5`), а
Unicode-минус приводится к понятному нормализатору дефису (`−5` → `-5`).
Короткое и длинное тире в начале строки по-прежнему считаются маркерами
реплики. В начале отдельной строки дефис перед порядковым числительным
(`- 62-й ранг`) также считается тире реплики, а не отрицательным числом.

На границе абзацев паузы не складываются. Обычная пауза между абзацами,
увеличенная пауза перед репликой/отдельной мыслью в одинарных или двойных
кавычках, пауза после двоеточия и соседняя пауза строки-разделителя сравниваются,
после чего вставляется одно наибольшее значение. Двоеточие распознаётся также
перед закрывающей кавычкой или скобкой, поэтому конструкция
`«Он подумал:»` корректно увеличивает паузу перед следующим абзацем.
Точные числовые паузы между абзацами применяются в режимах `sentence` и
`paragraph`. В режиме `full` абзацы входят в один большой запрос, поэтому их
внутренний ритм определяет модель по переводам строк; правило максимума всё
равно действует на явных строках-разделителях и защитных разрывах `SAFE_LIMIT`.

Программа не вводит дополнительную агрессивную очистку всей пунктуации в
начале фразы: это позволяет не повредить знаки чисел, формулы и ручные
ударения. Существующая очистка служебных символов и начального тире реплики
сохраняется.

Для MP3 обложка JPEG/PNG встраивается без повторного сжатия изображения. При
выводе в OGG текстовые теги сохраняются, но обложка пропускается с записью в
лог: Ogg/Vorbis не поддерживает JPEG/PNG как обычный поток `attached_pic`, а
старый способ мог завершить всю сборку ошибкой FFmpeg.

### Импорт и экспорт конфигурации

Профиль разделён на независимые группы: API и лимиты, пути, паузы, кэш,
эффекты, вывод/теги и значения вкладок. Если группа путей выключена, чужие
папки не импортируются. История файловых диалогов и размер шрифта являются
локальными предпочтениями и в профиль не входят. API Token считается секретом:
его импорт и экспорт требуют отдельной выключенной по умолчанию галочки.

## ⚙️ Установка и запуск

Ниже описан запуск **из исходников**. Основная и рекомендуемая ветка — **Python 3.13**; **Python 3.12** сохраняется как проверенный legacy-вариант. Python 3.14 и версии 3.11 и старше в текущую тестируемую матрицу не входят. Также нужны Tkinter и системные **FFmpeg/FFprobe**. Прямые Python-зависимости зафиксированы в `requirements.txt`. На Python 3.13 автоматически устанавливается `audioop-lts`, потому что модуль `audioop` удалён из стандартной библиотеки; Python 3.12 использует встроенный `audioop`. Готовые полные сборки уже содержат FFmpeg/FFprobe, а официальные артефакты воспроизводимо собираются в GitHub Actions на **Python 3.13.15** по полностью зафиксированному `requirements-release.txt`.

### Шаг 1. Установка FFmpeg/FFprobe для исходников и Portable-сборок

Этот шаг можно пропустить для полной Windows-версии в ZIP, полных Linux-версий в ZIP и macOS `.app`.
Системная сборка FFmpeg должна содержать кодировщики `libopus` и `libvorbis`;
обычные актуальные пакеты ниже их включают. GitHub Actions отдельно проверяет
эти кодеки перед упаковкой полных артефактов.

* **Windows:**
  1. Скачайте архив с FFmpeg (например, с [gyan.dev](https://www.gyan.dev/ffmpeg/builds/)).
  2. Распакуйте его в удобное место (например, `C:\ffmpeg`).
  3. Добавьте путь к папке `bin` (например, `C:\ffmpeg\bin`) в системные переменные среды `PATH`.
* **macOS:**
  Установите FFmpeg с поддержкой Opus/Vorbis через Homebrew:
  ```bash
  brew tap homebrew-ffmpeg/ffmpeg
  brew install homebrew-ffmpeg/ffmpeg/ffmpeg
  ```
* **Linux (Ubuntu/Debian):**
  ```bash
  sudo apt update && sudo apt install ffmpeg
  ```

### Шаг 2. Установка зависимостей Python

Рекомендуется устанавливать зависимости в отдельное виртуальное окружение. На macOS/Linux:
```bash
python3.13 -m venv .venv313
source .venv313/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip check
```
На Windows:
```powershell
py -3.13 -m venv .venv313
.venv313\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip check
```
Для legacy-запуска на Python 3.12 замените `python3.13` / `py -3.13` на 3.12 и используйте отдельное окружение, например `.venv312`. Важно запускать `pip` через тот же Python, которым затем запускается приложение. `audioop-lts` устанавливается только для Python 3.13; на Python 3.12 используется модуль стандартной библиотеки.

Команда `python3.13 SileroTTS_Studio.py` использует глобальное окружение Python 3.13, а не созданное выше виртуальное окружение. Поэтому ошибка `ModuleNotFoundError: No module named 'requests'` означает, что зависимости установлены не в тот интерпретатор. Предпочтительный запуск — после `source .venv313/bin/activate` командой `python SileroTTS_Studio.py` либо напрямую:
```bash
.venv313/bin/python SileroTTS_Studio.py
```

`requirements-release.txt` предназначен для воспроизводимой сборки готовых артефактов и фиксирует также транзитивные библиотеки и PyInstaller. ОС-зависимые пакеты PyInstaller перечислены с маркерами платформы, поэтому один файл подходит Windows, Linux и macOS. Для обычного запуска из исходников используйте `requirements.txt`; для локального повторения окружения GitHub Actions на Python 3.13 можно выполнить:
```bash
python3.13 -m venv .venv-release
source .venv-release/bin/activate
python -m pip install -r requirements-release.txt
```

Проверить Tkinter можно командой:
```bash
python -m tkinter
```
Официальные сборки Python с python.org обычно уже содержат Tkinter. Для Homebrew Python 3.13 установите соответствующий пакет Tk:
```bash
brew install python-tk@3.13
```
На macOS проверенная и рекомендуемая связка — **Python 3.13.15 + Tcl/Tk 9.0.x** (на момент выпуска проверена `9.0.4`). Она нужна не для основных функций синтеза, а для надёжного обновления уже открытого Aqua-интерфейса при переключении системной светлой/тёмной темы. Python 3.12 и Tk 8.6 по-прежнему поддерживаются: если оформление не обновилось на лету, перезапустите приложение после смены системной темы. Официальные macOS `.app` собираются с Tk 9.0.x и проверяются на эту версию в CI. Для Windows и Linux Tk 9 не является требованием; штатный Tk 8.6 поддерживается. Для Linux установите Tkinter командой `sudo apt install python3-tk`.

### Шаг 3. Запуск

В активированном окружении:
```bash
python SileroTTS_Studio.py
```
Без активации окружения на macOS/Linux:
```bash
.venv313/bin/python SileroTTS_Studio.py
```

## 🖥 Особенности работы на разных ОС

* **macOS (.app & .py):** Из-за ограничений безопасности Apple (Gatekeeper) скомпилированное приложение создаёт структуру проекта в `~/Documents/SileroTTS_Studio/`. Поддерживаются нативные горячие клавиши `⌘C`, `⌘V`, `⌘X`, `⌘A`, `⌘Z`, атомарный мультивыбор мышкой через `⌘-Click` и контрастные статусные палитры для светлого/тёмного оформления. Статус «Ожидание» относится к информационному цвету: тёмно-синему в светлой теме и небесно-голубому в тёмной. При восстановлении свёрнутого окна обработчики `Map`/`Activate` повторно применяют системный appearance, переустанавливают текущую ttk-тему и инвалидируют системные виджеты, чтобы нативные прогрессбары и ползунки не оставались серыми. Дочерние FFmpeg/FFprobe запускаются без небезопасного `fork` после инициализации Tk/CoreFoundation, поэтому параллельная сборка не должна выводить системное предупреждение `You MUST exec()`. Готовая `.app` уже содержит FFmpeg/FFprobe.
* **Windows:** Бесшумная работа фоновых утилит — окна командной строки не моргают при генерации и сборке (`CREATE_NO_WINDOW`). Полная версия поставляется папкой в ZIP и содержит FFmpeg/FFprobe; Portable-версия поставляется одним `.exe` и использует системные FFmpeg/FFprobe.
* **Linux:** Полная версия поставляется папкой в ZIP и содержит FFmpeg/FFprobe; Portable `onefile` поставляется в ZIP и использует системные FFmpeg/FFprobe.
* **Portable-режим:** При запуске `.py` из консоли на любой ОС, Windows Portable `.exe` или Linux Portable-бинарника рабочие папки создаются рядом с запущенным файлом. Для работы со звуком FFmpeg/FFprobe должны быть доступны в `PATH`.

## Диагностика частичного результата

Если итоговый MP3 создан, но получил статус **«Предупреждение»**, это означает,
что сборка формата завершилась, однако один или несколько речевых фрагментов
были заменены паузой после неудачных повторных попыток. В логе ищите исходную
причину (`HTTP 429`, ошибка API или ошибка локального декодирования), а не только
сообщение о сохранении MP3. На macOS при запуске из IDE/Finder приложение
использует абсолютные пути к встроенным или Homebrew `ffmpeg`/`ffprobe`, поэтому
урезанный `PATH` больше не должен приводить к сообщению `No such file or directory: 'ffprobe'`. Для Portable-сборок Windows/Linux системные бинарники по-прежнему
должны быть доступны в `PATH`.

Имена и содержимое файлов кэша вычисляются в UTF-8. После нормализации
самостоятельный чанк, в котором нет ни русских, ни ASCII-букв, не
отправляется: EnhancedTTS считает состоящий только из неподдерживаемых символов
фрагмент пустым и отвечает `HTTP 422: Your text is empty!`. Unicode-символы
внутри обычной поддерживаемой фразы не вычищаются, поэтому её payload и
существующий MD5-ключ кэша не меняются. Ожидаемый пропуск записывается в лог на
уровне `INFO`; ответы HTTP/API и локальные ошибки содержат короткие поля
`source` и `normalized`, а HTTP 422 дополнительно показывает безопасный
`detail` сервера и не повторяется пять раз. Цифры штатно превращаются
`ru-normalizr` в слова; если библиотека недоступна, отдельный чанк только из
цифр также пропускается вместо заведомого 422.
